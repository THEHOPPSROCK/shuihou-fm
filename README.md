**在线地址** · <https://thehoppsrock.github.io/shuihou-fm/> ｜ **仓库** · <https://github.com/THEHOPPSROCK/shuihou-fm> ｜ 托管：GitHub Pages（HTTPS）

## 1. 这是什么

「水喉FM」把「大水喉」这个水龙头 IP 变成一位**电台主播**，用户同它对话，就像打去一个粤语街坊电台：
查停水、交水费、问水压、学节水、报维修。

**项目设定（2026-11-17 补充，以此为准）**

| 项 | 设定 |
| --- | --- |
| 项目／产品名 | **水喉FM** —— 本 chatbot 的产品名 |
| 主播 | **大水喉**，目前**唯一**主播 |
| 品牌 | **「大水喉」家族**，东莞水务环境集团旗下**文创品牌** |
| 角色定位 | 大水喉＝品牌**官方发言人** |

家族其他成员（大旧水／李老表／关师傅／盖世宝）可以出场客串，但都不是主播。
这四条已经写进真实频道的 system prompt（`assets/js/chat.js`）、自我介绍与「家族成员」问答（`assets/js/data.js`）。

命名不需要另起：**《大水喉世界观》2.1 明确写着同事昵称就是「水喉 FM」**，本设计把它从一句设定做成一个产品。
「96968 频道号」、台呼、节目表属于**本次设计提案**（品牌资产里只有「水喉FM 提提你……」这一条既定播报句式），提案部分在 `assets/js/data.js` 中单独标注。

页面分两件：

| 文件 | 用途 |
| --- | --- |
| `index.html` | **主入口**：移动优先——精简台标 + 单栏全屏对话 + ☰ 收纳目录 |
| `app.html` | 旧链接兼容页，自动跳转 `index.html` |
| `assets/` | 字体子集、矢量标志、角色插画（WebP）、样式与脚本 |
| `_research/` | 过程文件：手册提取文本、API 调研、构建脚本、截图（可整包删除） |

## 2. 怎么跑

```bash
cd dshuihou
python -m http.server 8811     # 或 pnpm dlx serve / 任意静态服务器
# 打开 http://127.0.0.1:8811
```

页面用的是 ES module，**必须经 HTTP 打开**；直接双击 `index.html` 时页面会给出提示条。

两种模式（右上角 ⚙ 调频里切换）：

- **录播 DEMO**：默认。本地剧本 + 逐字「录播」、思考块、搜索卡片、来源角标、自动命名全部可以玩，不发任何真实请求；剧本数据均标注为演示。
- **真实频道**：填入自己的 DeepSeek API Key（只存 localStorage，浏览器直连 `api.deepseek.com`，已实测该接口对浏览器开放 CORS），走真实流式对话：联网搜索、深度思考、文件解析、朗读、语音输入、会话标题、内容安全全部接通。

## 3. 设计语言：从手册里长出来

### 3.1 三色（IP 手册 C 1）

| 角色 | 色值 | 印刷 | 用途 |
| --- | --- | --- | --- |
| 水喉黄 | `#FFD017` R255 G208 B23 | C0 M20 Y100 K0 · PANTONE 116 C | 主色：高亮、CTA、水喉本体 |
| 大水蓝 | `#0094DD` R0 G148 B221 | C75 M25 Y0 K0 · PANTONE 2193 C | 水流、开关、次强调 |
| 深水蓝 | `#004384` R0 G67 B132 | C100 M75 Y0 K0 · PANTONE 2186 C | 描边、正文、深底 |

辅助色沿用 C 1.2–C 1.5：水阀红 `#FD3C44`（ON AIR 红灯）、水阀蓝 `#3B80FF`、水塔棕 `#D18354`、井盖灰 `#9CA6B0`。
品牌标识另有一套 VI 双色（`#FFDA00` / `#00BCFF`，A 6.1，PANTONE 109 C / 306 C），仅用于标志与品牌设备，不与 IP 三色混用。

页面里写了一个 **6 : 3 : 1** 的用色比例条：黄占大面积，蓝只落在「水」和「广播」的位置，其余交给纸白。

> 色彩管理说明：手册原始色彩空间为 Adobe RGB，并要求「线上电子物料使用 RGB 色值」「不得直接把 Adobe RGB 数值写成网页 HEX」。本页的 HEX 是**屏幕工作值**，正式交付前应按手册流程做一次 Adobe RGB→sRGB 核对。

### 3.2 字体（VI 手册 A 5）

- 标题：**小赖字体 等宽 SC Regular**（手册要求「描边根据字体大小调整粗细，以接近字体规范粗度」——网页用字重补偿替代印刷描边）
- 正文：**JinzisheDezheng Regular**
- 英文：**Winky Rough Bold Italic**（大量用在 `ON AIR`、`96968`、节目编号 `B 02-1`）

三套字体都做了**子集化**（只保留页面实际用字，22 MB → 126–167 KB），见 `assets/fonts/`。
JinzisheDezheng 缺粤语字（嘅、喺、咗、啫、唔），页面按 font stack 自动回落小赖字体——正文里的粤语助词因此会带一点手写感，这是取舍后的结果，并非错字。

### 3.3 形状

- 粗描边：`2.5px` 深水蓝，向 IP 的粗线靠拢；卡片 `22–34px` 圆角
- 硬投影：`4–6px` 无模糊偏移，像贴纸一样「贴」在纸上
- 纸张颗粒：全站叠一层 8 KB 的噪点底纹，替代手册里的「粗糙化」效果
- 三股水柱：标志里的三条水流被抽出来当作**电平/加载动画**（`.typing`、`.signal`），是这套设计里最好用的一个图形梗
- 水管：A 11.1「水龙头水管方向可无限拉长」→ 首屏顶部的黄色水管条 + 管口套环（收窄前的落地页有，已备份在 `_archive/index-landing-showcase.html`）

### 3.4 标志

直接从 `D-大水喉-LOGO-R标-2026-0814.ai` 的矢量路径里提取，重新合成为 SVG：

- `logo-h` 横式组合（主用法）、`logo-stack` 竖式
- `logo-h-white` 反白（深底）、`logo-h-ink` 单色（黄底/浅底）
- `logo-icon` 纯图标（水龙头 + 三股水柱 + ®）

用法遵循 A 7 / A 8：深底反白、浅底品牌色、黄底单色；不做线稿、不改比例、不加投影。备份版首屏黄色水管上的图标之所以用**深蓝单色**，正是 A 6.3 的规定——黄色标志放到黄色底上会糊掉。

### 3.5 语气

依据《大水喉世界观》2.4（热心可靠 / 最可爱的反差 / 不善求助的成长线）：

- 会讲：「水喉FM 提提你：」「有我喺度」「小事啫」「辛苦晒大家」「唔使慌」
- 会做：先答问题，再提一句；讲唔清楚就认，指去「转人工」/ 0769-96968 供水热线；被感谢时谦让一句
- 唔会讲：「严禁」「必须」；夸张承诺；编造停水时间同水费金额
- 保留粤语原句「水嘅事，就系大事」，普通话释义只作注解

真实频道里这段规则写进了 system prompt（`assets/js/chat.js` 的 `SYSTEM_PROMPT`）。

## 4. 界面：一间收音机房

> **2026-11-17 起改为移动优先**：右栏删除，左栏收进 ☰ 抽屉，对话占满屏幕；下面保留原始三栏草图作设计沿革记录。

直播室原本是**三栏**结构，像电台控制台：

```
┌──────────┬───────────────────────────────┬──────────────┐
│台标/96968│  节目条 · 会话标题 · 安全播出    │  主播间       │
│ 今日节目表│  对话区（广播稿 / 听众来电）    │  角色状态     │
│ 饮水打卡  │  输入区（文件/语音/联网/谂深啲）│  今日金句     │
│          │                               │  贴纸 · 信号  │
└──────────┴───────────────────────────────┴──────────────┘
```

对话被重新命名为广播语言：

- 用户消息 = **听众来电**（黄底、右下尖角）
- 助手消息 = **广播稿**（无气泡，左边主播头像 + 「主播」标签 + 开场白「水喉FM提提你：」）
- 思考过程 = **水龙头飞速转紧**（默认折叠，只留一行状态「谂紧…／已完成」；点开才见到推理原文）
- 联网搜索 = **查紧资料**（默认折叠，只留一行「N 个来源」；点开才见到站点、标题、摘要）
- 引用 = **角标 ①②③**，点击跳到下方「参考来源」
- 打字 = 三股水柱跳动
- 会话标题 = 节目名（真实频道由 `title` 能力自动生成，显示「自动命名」）
- 拒答 = **安全播出 · 已拦截**
- 大水喉贴图 = 空态那只可点击的贴图（有「㩒一下 · 睇动画」提示）→ 播放 9:16 品牌动画（12 秒，**只播一次**，可跳过）→ 播完自动出一段反馈「今日你饮水未？」+ 饮水贴图
- 收纳目录 = ☰ 打开左侧抽屉（品牌卡 + 今日节目表 + 饮水打卡）；点背景/关闭/选节目都会自动收起
- 导入对话历史 = ⚙ 设置 →「选择 DeepSeek 导出文件…」，自动识别最后一段对话并铺回聊天窗（本机解析，不上传）
- 转人工 = 输入框工具栏「谂深啲」右侧的**红色按钮** → 手机底部弹出的快捷拨号面板，显示【客服热线：0769-96968】，点「立即拨打」唤起系统电话 App（`tel:`），桌面端可复制号码
- 快捷问句 = 收起喺空态（未开始对话时显示 3 条）；发出第一条后自动消失，清空对话会再出现

主播头像会随状态换表情（谂紧/查紧/写紧/播紧/答完/塞咗/待机），全部取自 IP 现有插画，没有新增造型。

## 6. 素材处理（做了什么、为什么）

1. **插画取色校正**：提供的 25 张 `素材png` 是 CMYK 印刷稿导出的 sRGB 图，实色落在 `#F3D031 / #5394DD / #254280`，比手册规定的屏幕 RGB 暗一档。为让插画与界面同色，按三个品牌锚点做了色域校正（保留各图内部明暗关系，绿/棕/粉/灰不动），输出 `assets/img/ip/*.webp`。原图未改动。
2. **矢量标志**：从 `.ai` 的 PDF 兼容层读取 160 条矢量路径，按组合拆分、重着色、生成 SVG，比位图标志更锐利。
3. **字库子集**：用 `fonttools` 裁到页面实际用字并转 woff2。
4. **裁边**：角色插画统一裁掉透明边、留 2.5% 余量、最长边 760 px、WebP q90（全套约 1.3 MB）。

构建脚本都在 `_research/`（`build_logos.py`、`build_images.py`、`recolor_assets.py`、`trim_assets.py`、`build_fonts.py`），可复跑。

## 7. 声线（D01 声线试镜）

单独一页：`voice.html`（＝ http://127.0.0.1:8811/voice.html）。
入口收喺直播室右上角 **⚙ 设置 →「声线试镜 · D01」**（唔再直接放喺台标栏）。

**定调**：一个二十几岁、住喺东莞、记得你屋企几点停水嘅街坊；唔系大叔播音腔，亦都唔系甜妹。
《大水喉世界观》2.1 **未定义性别同年龄**，所以「偏中性」是顺着设定，不是回避。

**两条入围声线**（Azure / Edge 同一把声，30 秒四拍台词：开台／停水提醒／被赞害羞／忙到晕）：

| 声线 | voice ID | 调参 | 中位 F0 | 取向 |
| --- | --- | --- | --- | --- |
| **WanLung 原声** | `zh-HK-WanLungNeural` | +0% / +0Hz | 113 Hz | 稳、有担当——问答／报修／停水通告 |
| **HiuMaan 原声** | `zh-HK-HiuMaanNeural` | +0% / +0Hz | 242 Hz | 活、年轻——开台／贴士／短句互动 |

两条正好落在音高两端（113 / 242 Hz），中间没有重叠，所以这是一次「取向投票」，不是微调。
早前试过的 5 条调参变体（HiuGaai 原声／−16Hz、HiuMaan −18Hz、WanLung +22Hz／+40Hz）已移到 `_archive/audio-voice/`，随时可取回。

F0 为 30 秒样本自相关法中位数，只作筛选参考；最终要人耳盲测（页面内附协议与粤语破绽检查清单）。

**云端更贴角色的备选**（需 Key）：MiniMax `Cantonese_PlayfulMan`（最会演害羞／忙乱）、`Cantonese_ProfessionalHost (M/F)`、腾讯云 `404000 云佳妍（广）`、阿里云 `longjiayi_v3`、Azure `yue-CN-YunSongNeural / yue-CN-XiaoMinNeural`、ElevenLabs v3（`yue` + Voice Design 可造专属声线）。完整的音色目录与出处见 `_research/voice_catalog.md`。

## 8. 已知边界
- **录播剧本是演示内容**：停水时间、来源站点、水费说明均为示意，不代表真实查询结果，页面内已标注。
- **96968 频道号、台呼、节目表、主播间** 是本次设计提案，品牌既有资产里没有，属可讨论的延展。
- 真实频道需要用户自带 API Key；页面不设后端，Key 存 localStorage，浏览器直连 DeepSeek（CORS 已实测可用，但仍建议正式产品走服务端代理，避免 Key 暴露）。
- 朗读：真实频道走 DeepSeek TTS（`stella` / `tide`）；录播模式退回浏览器 `speechSynthesis`（有粤语声线则用粤语）。
- 语音输入：录播模式用浏览器 `SpeechRecognition`；真实频道录 MediaRecorder → 转 16 kHz WAV → `/v1/tools/asr`（MediaRecorder 的 webm/opus 接口不收，必须转码）。
- 兼容性：Chrome / Edge 最新版最佳；`backdrop-filter`、`color-mix`、`aspect-ratio` 需要较新浏览器。

## 10. 加载性能

`index.html` 是「零外链单文件」成品：CSS、JS、标志、空态贴图全部内联；空态先用静态 HTML 画出，脚本初始化排到 `requestIdleCallback`；品牌动画视频 `preload="none"`，点了才加载。

| 指标（本机 8811 · 冷缓存 · 6 次平均） | 改版前 | 现在 |
|---|---|---|
| 请求数 | 14 | **4**（HTML + 3 个字体） |
| 传输量 | 544 KB | **340 KB**（字体占 330 KB） |
| TTFB | 2.7 ms | **2–3 ms** |
| DOMContentLoaded | 89.6 ms | **17–19 ms** |
| 首屏绘制 FCP | 16 ms± | 与空白页同速（相对增量为 0） |

> 关于 FCP：同一测量环境下**空白页**的 FCP 也要 105–160 ms（浏览器启动/合成器底噪），所以看「页面相对空白页的增量」更准——现在增量≈0，即首屏渲染本身不花时间。
> 字体用 `font-display: swap`：先用回退字体上屏，字体下载完再换字形，不阻塞首屏；这也是 `load` 事件（≈70 ms）比 DCL 晚的原因。
> 网络部署（GitHub Pages）时，物理下限由网络 RTT 决定（跨境 CDN 首字节 ~150–400 ms），任何页面都压不进 20 ms；20 ms 级指标只有在本地/内网/已缓存场景成立。

> **维护方式**：`index.html` 由 `_src/index.template.html` + `_research/tools/build_min.mjs`（esbuild）生成。改文案先改模板（或 `assets/js/*`），再运行 `node _research/tools/build_min.mjs` 重建，然后 `git push`。
